# Dependencies

`scadactl` coordinates installed system capabilities. It does not bundle GPU
drivers, storage drivers, domain servers, or Storage Lender.

## Python dependencies

| Component | Requirement | Purpose |
| --- | --- | --- |
| Python | 3.10 or newer | CLI runtime |
| PyYAML | Required | Configuration and policy parsing |
| `nvidia-ml-py` | Required for GPU-aware commands | Provides the `pynvml` module |
| pytest | Development only | Hardware-free test suite |
| build | Development only | Source archive and wheel builds |
| setuptools | Build only | Python package build backend |

Python dependencies are resolved and installed separately by the selected
Python or operating-system package manager. They are not copied into this
repository or its source archive.

## Host utilities

| Capability | Commands or package | Used by |
| --- | --- | --- |
| NVMe discovery | `nvme` (`nvme-cli`) | Inventory and stable identity |
| Process inspection | `fuser` (`psmisc`) | Safe reconciliation and teardown |
| Process management | `pgrep`, `pkill` (`procps`) | MPS detection and explicit force-stop recovery |
| Block-device inspection | `lsblk` (`util-linux`) | Advisory drive availability |
| Shell runtime | Bash 4+ | Domain manager |
| NVIDIA management | `nvidia-smi` | GPU index resolution by the domain manager |
| CUDA MPS | `nvidia-cuda-mps-control` | MPS lifecycle when enabled |

The Debian package declares the generally available host utilities. NVIDIA
driver and CUDA components remain deployment-specific.

### util-linux component licensing

The util-linux executable called by this project is `lsblk`, licensed under
**GPL-2.0-or-later**. It is executed as a separate process; its source and binary
are not bundled with this project. See the
[upstream lsblk copyright and license notice](https://github.com/util-linux/util-linux/blob/v2.39.3/misc-utils/lsblk.c).

Registry locking uses Python's standard-library `fcntl.flock`, not the util-linux
`flock` executable. The project does not invoke util-linux `mount`, `umount`,
`findmnt`, or `setsid`.

## Debian packaging dependencies

Debian packaging uses `debhelper-compat (= 13)` and the `dh` sequencer with
`--buildsystem=none`. The value 13 selects a compatibility level, not a specific
debhelper package version. These are build-time tools installed separately,
not software linked into or vendored in scadactl.

| Component | Applicable license | Packaging role |
| --- | --- | --- |
| `dh`, `Debian::Debhelper` sequencing/build-system modules | GPL-2.0-or-later | Select and orchestrate the packaging sequence |
| `dh_testdir`, `dh_testroot`, `dh_prep`, `dh_clean`, `dh_installdirs` | GPL-2.0-or-later | Check and prepare the package staging area |
| `dh_auto_clean`, `dh_auto_configure`, `dh_auto_build`, `dh_auto_install` | GPL-2.0-or-later | Default build-system steps; automatic upstream build/install is disabled by `--buildsystem=none` |
| `dh_install`, `dh_installdocs`, `dh_installchangelogs` | GPL-2.0-or-later | Install project files and documentation |
| `dh_link`, `dh_compress`, `dh_fixperms`, `dh_missing` | GPL-2.0-or-later | Process staged package contents and check installation completeness |
| `dh_installdeb`, `dh_gencontrol`, `dh_md5sums`, `dh_builddeb` | GPL-2.0-or-later | Generate package metadata and assemble the Debian archive |
| `dh_installinit` | GPL-3.0-or-later | Default sequence helper for init scripts; this project supplies no init scripts |
| debhelper `autoscripts/*` | Public domain, with an alternative permissive grant in the upstream copyright file | Maintainer-script snippets, if generated by the packaging helpers |

The `dh_auto_test` step is overridden to run `python3 -m pytest`; the project
does not enable a `dh_python` or `pybuild` addon. Default helpers for features
not supplied by the project may be skipped or perform no work. In particular,
the older BSD-3-Clause helpers `dh_systemd_enable` and `dh_systemd_start` are not
used at compatibility level 13.

The component licenses above are documented in
[debhelper's file-specific copyright metadata](https://sources.debian.org/src/debhelper/14.5/debian/copyright/).
To record the package version and review the selected sequence on a Debian
build host, run from the repository root:

```sh
dpkg-query -W -f='${Package} ${Version}\n' debhelper
dh clean --buildsystem=none --no-act
dh binary-indep --buildsystem=none --no-act
```

Dry-run output includes helpers that a real build may skip. The installed
debhelper package's `/usr/share/doc/debhelper/copyright` and actual build log
are the references for the build environment; sequence addons and additional
tools pulled in by that environment require their own dependency assessment.

## Runtime capabilities

| Feature | Installed capability |
| --- | --- |
| Domain lifecycle | `manage-scada-domains` from this project and a compatible `scada-swap-domain` binary |
| Kernel storage backend | `/usr/sbin/scada-load-modules`, `/usr/sbin/scada-unload-modules`, and the UNVMe driver/runtime |
| Lender storage backend | Storage Lender service and socket plus a lender-compatible `scada-swap-domain` |

The kernel and lender backends are alternatives. Installing this repository
alone provides the control plane and domain manager, but not either backend's
driver, service, or domain-server implementation.

## Third-party policy

No third-party software source is vendored in this repository. The DCO text in
`CONTRIBUTING.md` and the adapted Contributor Covenant in `CODE_OF_CONDUCT.md`
are third-party documentation; their notices and copying terms are recorded in
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) and the documents themselves.

Adding copied, generated,
statically linked, or redistributed third-party content requires updating the
project notices with the component name, version, source, license, and required
license text before release.
