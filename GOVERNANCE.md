# Governance

`scadactl` uses a maintainer-led governance model.

## Roles and decisions

Maintainers own technical direction, issue triage, reviews, releases, and
repository operations. Current ownership and role membership are defined in
[MAINTAINERS.md](MAINTAINERS.md) and [`.github/CODEOWNERS`](.github/CODEOWNERS).

Routine decisions are made through issue and pull-request review. Changes to
public CLI behavior, configuration schemas, security boundaries, dependency or
license posture, packaging, or governance require explicit maintainer review.
Maintainers seek technical consensus but may decide when consensus is unavailable
and document material tradeoffs.

## Project stewardship

Maintainers carefully consider community feedback and retain final responsibility
for project scope, technical direction, contribution acceptance, and releases.
Participation or submission does not guarantee acceptance or a delivery timeline.

## Security and conduct

Potential vulnerabilities are escalated privately to NVIDIA PSIRT under
[SECURITY.md](SECURITY.md). Conduct matters are handled under
[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Governance changes

Governance changes use the normal review process and require maintainer approval.
